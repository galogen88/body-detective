# Боди Детектив — план демо v0.1 «Зажимы»

Полная версия плана с идеями на потом: https://claude.ai/artifact/Swb3bsanSunvVrx15AL7Pv

Цель v0.1: 3D-атлас в браузере, наведение на сосуды кровеносной системы и одна мини-игра — поставить зажим на сосуд с пробоиной с правильной стороны. Затем деплой на Vercel.

## Шаг 0. Подключить атлас к этому репозиторию (сделать первым)

Репозиторий `BodyDetective` пока содержит только `docs/` и `CLAUDE.md`, кода нет. Атлас [ashemag/human-atlas](https://github.com/ashemag/human-atlas) (React + TypeScript + Three.js) становится основой проекта: его код вливается сюда, а `docs/` и `CLAUDE.md` остаются.

1. Подключить атлас как `upstream` и влить его историю:
   ```bash
   git remote add upstream https://github.com/ashemag/human-atlas.git
   git fetch upstream
   git merge upstream/main --allow-unrelated-histories
   ```
   Конфликтов быть не должно: в атласе нет `docs/` и `CLAUDE.md`. Если конфликт всё же есть — остановиться и спросить Диму.
2. Создать свой репозиторий на GitHub, добавить его как `origin`, запушить — он понадобится для Vercel.
3. Обновления атласа потом подтягивать через `git fetch upstream && git merge upstream/main`.

Старый каркас `~/IdeaProjects/body-detective` (Vite + чистый JS) в v0.1 не используется.

## Что важно знать об атласе

- React + Three.js + Vite + TypeScript, Node.js 22.13 или новее, dev-сервер на `localhost:3016`.
- 2 234 меша BodyParts3D, 15 систем, около 33 МБ сжатой геометрии.
- Меши склеены в общие пачки; видимость и выделение каждой структуры — через GPU-текстуры, а не отдельные материалы.
- Код — MIT, анатомические данные — CC BY 4.0: атрибуцию BodyParts3D (`public/ATTRIBUTION.md`) сохраняем.

## Этапы

1. **Форк и запуск**
   - `npm ci`, `npm run dev`. Своя работа — в ветке `game`; изменения атласа приходят из `upstream`.
   - Готово, когда: атлас открывается на localhost, проходят `npm run check` и `node scripts/validate-atlas.mjs`.
2. **Разбор кода атласа**
   - Найти, где хранятся имена структур и принадлежность к системам, как работает выбор по клику (picking).
   - Найти механизм подсветки выделенной структуры, чтобы переиспользовать его для наведения.
   - Готово, когда: есть заметка `docs/atlas-notes.md` — какие файлы и функции трогаем.
3. **Только кровеносная система**
   - Пресет «Кровеносная система», остальные системы скрыты.
   - Тип сосуда (артерия / вена) берём из названия меша (artery / vein), исключения правим вручную.
   - Артерии красные, вены синие.
   - Готово, когда: на экране только сосуды и сердце, раскрашенные по типу.
4. **Наведение мышкой**
   - `pointermove` с ограничением частоты (~30 раз в секунду): подсветка сосуда + подсказка «название + тип».
   - На телефоне то же действие по тапу.
   - Готово, когда: FPS не падает ниже ~30 на обычном ноутбуке.
5. **Игра «Заделай пробоину»**
   - `src/game/vessels.json`: 4 сосуда (бедренная артерия и вена, плечевая артерия и вена); для каждого — тип и точка «конец ближе к сердцу».
   - Раунд: случайный сосуд, на нём пробоина (мигающая метка). Игрок кликает по сосуду — ставит зажим.
   - Правило: зажим ставится выше по течению, со стороны, откуда идёт кровь.
     - Артерия (кровь от сердца): зажим ближе к сердцу, чем пробоина.
     - Вена (кровь к сердцу): зажим дальше от сердца, чем пробоина.
   - Проверка: проецируем позиции зажима и пробоины на прямую между концами сосуда и сравниваем расстояние до конца «ближе к сердцу».
   - Верно — кровь останавливается, +очко, следующий раунд. Неверно — подсказка про направление тока крови.
   - Готово, когда: 5 раундов подряд проходятся без ошибок в логике проверки.
6. **Деплой**
   - Импорт репозитория в Vercel (Hobby, бесплатно для некоммерческого проекта); `vercel.json` уже есть: `npm ci`, `npm run build`, папка `dist`.
   - Push в `game` — preview-ссылка, push в `main` — основная.
   - Запасной вариант: Netlify / Cloudflare Pages; для GitHub Pages настроить `base` в `vite.config.ts`.
   - Экран «Титры» с атрибуцией BodyParts3D.
   - Готово, когда: ссылка открывается на ноутбуке и телефоне, игра доигрывается до конца.

## Риски и решения

| Риск | Почему проблема | Что делаем |
| --- | --- | --- |
| Нет направления тока крови | Меш — трубка без оси; «выше по течению» модель не знает | Для 4 сосудов вручную задаём точку «ближе к сердцу», проецируем на прямую между концами |
| Изогнутые сосуды | Проекция на прямую врёт на изгибах (дуга аорты) | В v0.1 только прямые сосуды конечностей |
| Подсветка через общие пачки | Цвет одного сосуда материалом не поменять | Переиспользуем механизм выделения атласа; выясняем на этапе 2 |
| Наведение тормозит | Поиск по ~2,3 млн треугольников на каждое движение мыши | Ограничение частоты, поиск только среди видимых сосудов |
| На телефоне нет hover | Ключевая механика v0.1 | Тап = наведение + выбор; проверить на реальном телефоне |
| Тонкие сосуды трудно попасть | Мелкие при общем виде тела | Камера приближается к конечности при старте раунда; зона клика с запасом |
| 33 МБ геометрии | Долгая первая загрузка | Экран загрузки с прогрессом; позже — сборка только с кровеносной системой |
| Исключения в анатомии | Лёгочная артерия несёт венозную кровь, воротная вена идёт не к сердцу | В v0.1 таких сосудов нет; цвет — по типу сосуда |
| Упрощение медицины | В реальной травме часто зажимают с обеих сторон | Подпись в разборе раунда + дисклеймер «учебная игра, не медицинская инструкция» |
| Форк отстаёт от оригинала | Атлас развивается, правки трудно подтягивать | Игровой код в `src/game/`, правки в коде атласа минимальные |
| Расползание объёма | «Детектив с уликами» и «зажимы» — две игры | v0.1 — только зажимы; детектив — v0.2 |
